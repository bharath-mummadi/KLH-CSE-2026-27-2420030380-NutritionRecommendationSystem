## Methodology

The system follows a five-stage pipeline: data integration across three
sources, feature engineering, parallel prediction and constraint
enforcement, hybrid recommendation, and explainability/evaluation. NHANES
defines what a person needs; USDA and Food.com define what can be
recommended to meet that need. The prediction and constraint layers run
independently — not sequentially — so medical safety rules can override a
prediction rather than just influence it.

---

## System Design

**Architecture (6 layers):**
```
Data Layer            -> NHANES + USDA + Food.com (cleaned, linked)
Feature Layer          -> BMI, TDEE, biomarker risk flags
Prediction Layer        -> Stacked ensemble (LightGBM + XGBoost + RF)
Constraint Layer         -> Biomarker-based hard safety filters (parallel to Prediction)
Recommendation Layer    -> RAG retrieval + content + collaborative filtering
Output Layer            -> SHAP explainability + demo/evaluation report
```

## Implementation

**Stacked Ensemble** — `src/train_ensemble.py`
```python
base_learners = [
    ("hist_gb", HistGradientBoostingRegressor(max_depth=5)),   # LightGBM-analog
    ("grad_b", GradientBoostingRegressor(n_estimators=200, max_depth=3)),  # XGBoost-analog
    ("rf", RandomForestRegressor(n_estimators=300, max_depth=8)),
]
model = StackingRegressor(
    estimators=base_learners,
    final_estimator=Ridge(alpha=1.0),
    cv=5,
)
model.fit(X_train, y_train)
```

**Constraint Layer** — `src/constraint_layer.py`
```python
def apply_constraints(predicted_calories, predicted_carbs_g, row):
    messages = []
    adj_carbs = predicted_carbs_g

    if row.get("DIABETIC_FLAG", 0) == 1 or row.get("HBA1C", 0) >= 6.5:
        cap = adj_carbs * 0.75
        if adj_carbs > cap:
            messages.append(f"Carb target reduced to {cap:.0f}g due to elevated HbA1c.")
            adj_carbs = cap

    if row.get("HYPERTENSION_FLAG", 0) == 1 or row.get("CHOLESTEROL_MGDL", 0) >= 240:
        messages.append("Flagged for reduced saturated-fat / sodium recommendations.")

    return predicted_calories, adj_carbs, messages
```

**Verified test cases** (run `python src/constraint_layer.py` to reproduce):
- Diabetic profile (HbA1c 7.2%) -> carb target reduced from 220g to 165g
- Healthy profile (HbA1c 5.1%) -> no adjustment, passes through unchanged

**Feature Engineering** — `src/preprocess.py`
```python
def engineer_features(df):
    df["GENDER_M"] = (df["GENDER"] == "M").astype(int)
    df["ACTIVITY_SCORE"] = df["ACTIVITY_LEVEL"].map({"low": 1, "moderate": 2, "high": 3})

    def bmi_cat(b):
        if b < 18.5: return "Underweight"
        elif b < 25:  return "Normal"
        elif b < 30:  return "Overweight"
        return "Obese"
    df["BMI_CATEGORY"] = df["BMI"].apply(bmi_cat)
    return df
```

## Performance Evaluation

- **Stacked ensemble matches or slightly beats the best individual base
  learner** (Random Forest) — the theoretically expected behavior of
  stacking, since the meta-learner can down-weight weaker base learners.
- **Biomarkers correctly show near-zero importance in calorie
  prediction** — confirms the two-layer design works as intended:
  biomarkers act through the independent constraint layer, not the base
  prediction.
- **Constraint layer verified correct on both edge cases** — activates
  only for diabetic-range biomarkers, leaves healthy profiles untouched.
- **Benchmarked against prior work:** existing papers report up to 87.6%
  accuracy (simple-averaged ensemble) and F1 0.972 (best single-model
  classifier) on their own classification tasks; this project additionally
  reports regression metrics (RMSE/MAE/R2) and is designed to report
  Precision@K, NDCG, and hallucination-rate once the recommendation layer
  is complete — metrics absent from all ten reviewed papers.
- **Caveat to state on the slide:** current numbers are from a synthetic
  NHANES-structured dataset (development sandbox has no internet access to
  download real NHANES data or install LightGBM/XGBoost/SHAP); the
  pipeline and evaluation logic are real and already executed, and will be
  re-run on real data and production libraries as a documented one-line
  swap (see `docs/methodology.md`).
